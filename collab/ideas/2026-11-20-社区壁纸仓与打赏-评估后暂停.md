# 想法：社区壁纸仓 + 打赏（评估后暂停）

- 日期：2026-11-20
- 提出：用户
- 状态：**暂停，暂不实施。** 记录在此，等触发条件满足再重启，不要重复论证。

## 原始设想（用户的版本）

做一个免费开源的壁纸仓库，别人把自己做的壁纸上传进来；有人用/买，就付钱给他；平台从中获得价值。国内网络不便，所以 GitHub + Gitee 双份。

## 结论

**方向对，顺序错。** 现在做等于在没有流量的地方建商场；而且有一条比商业风险更硬的技术风险（见下）。最终采用的形态是：**免费社区 + 打赏，平台不碰钱**。但整个功能**暂停**。

## 为什么暂停（六条，按严重程度排）

1. **安全：应用会执行别人写的 JS。** 像素幻境支持"装自制壁纸（单文件 HTML）"。开放上传下载 = 把任意 JS 分发到用户电脑：读本地文件、盗剪贴板、伪装设置页诱导点击。必须先在架构上有隔离窗口、禁网、静态扫描、签名清单，否则做社区就是分发恶意代码的工具。这条是硬门槛。
2. **仓库结构：壁纸不能进软件主仓库。** 三个理由：体积会被撑爆（1000 件就是几百 MB）；git 历史删不干净（侵权内容删了还在历史里，投诉永远处理不完）；社区不该有主仓库写权限。正确拆法是代码仓 + 内容仓 + 一份索引（`wallpapers.json`）。
3. **合规：一收费就变"经营性平台"。** 需要企业主体、支付通道、发票与税务、退款、内容审核；不收费则全部规避。**打赏必须直接进作者自己的口袋**（作者贴爱发电/收款码，客户端只跳转），平台代收就等于自己把合规成本扛上来。
4. **版权：壁纸是盗版重灾区。** 上传内容很可能是从 Wallpaper Engine 创意工坊或网图扒的。一旦收费，平台责任认定就变了，需要通知-删除机制、投诉入口、下架流程、作者身份核验。
5. **双边冷启动。** 创作者不来没有流量、没有流量创作者不来。Wallpaper Engine 有百万用户 + 创意工坊才成立。
6. **和现有卖点冲突：「完全离线、不联网、不收集任何信息」。** 加了社区列表就破了这个口径。要做只能这样处理：能力保留、默认关闭、只在用户点"社区"时联网、页内写明"只请求索引和预览图"、绝不做遥测或后台心跳，隐私页逐条列出哪些操作会联网。

## 重启的先决条件（数字门槛，达不到就不做）

- 月活 ≥ 现有用户量的 10 倍（先证明产品有人用）
- 每周新增原创壁纸 ≥ 10 件（先证明有人愿意做）
- 社区功能的四个前置件就位：隔离沙箱、壁纸包签名与校验、上门审核流程、隐私页更新

## 重启时的最小落地路径

1. 立规范：`manifest.json` 字段、目录结构、大小上限、哈希算法 + 一个本地校验脚本（以后 CI 直接跑同一个）
2. 建两个仓库（代码仓不动；内容仓 `pixelfx-community` 接受 PR），放 3 个自建示例壁纸，把 PR → 校验 → 合并这条路走通
3. 软件加社区入口：读索引 → 下载 → 本地缓存 → 沙箱执行 → "支持作者"按钮
4. 最后才是推广

## manifest 草案（重启时按这个起步）

```json
{
  "id": "starfield-01",
  "name": "星野",
  "author": { "name": "...", "home": "..." },
  "version": "1.0.0",
  "license": { "personal": "free", "commercial": "paid", "redistribute": false, "modify": "author-only" },
  "entry": "entry.html",
  "preview": "preview.png",
  "bytes": 123456,
  "sha256": "...",
  "support": [
    { "type": "link", "label": "爱发电", "url": "https://afdian.com/a/xxx" },
    { "type": "qr", "label": "微信赞赏", "file": "qr-wechat.png" }
  ]
}
```

配套目录：`wallpapers/<id>/{manifest.json, preview.png, entry.html}`，`wallpapers.json` 由 CI 从各 manifest 汇总生成，**客户端只信任索引里的条目**（审核通过 = 出现在索引里）。

## 双源策略

- 主仓在 Gitee（国内 PR/审核更顺），GitHub 定时镜像
- 客户端内置两个源：**Gitee 优先、GitHub 兜底**，每个源 3 秒超时，失败换下一个
- 成功拉到索引后本地存一份，离线时显示缓存并标注"缓存"
- 别依赖 `raw.githubusercontent.com`（国内不稳）；真要不稳，再补一份自己对象存储上的索引（几元/月）

## 与现有"打赏"待办的关系

STATE 里那条"打赏：Microsoft Store 消耗型附加组件（¥6 / ¥18）"是**给软件本身打赏**；这里说的是**给创作者打赏**。两件事，不要混。

## 一句话

等产品有人用了、有创作者愿意做了，再从"规范 + 校验脚本"这两步开始。在那之前，谁再提"做社区市场"，先看这份文件的六条暂停原因。
