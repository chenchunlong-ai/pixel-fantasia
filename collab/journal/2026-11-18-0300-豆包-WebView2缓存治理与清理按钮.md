# WebView2 缓存治理：上限、组件下载抑制、设置页清理按钮

- **Agent**: 豆包  **Task**: 让「不到 1MB」这句宣传在安装后也站得住，并给出可点的一键清缓存  **时间**: 2026-11-18 03:00

## 改动

5 个文件（其中 1 个是构建生成物）：

- `shell/Program.cs`（+85 行）
  - `EnvOptions()`：`CreateAsync` 的第二参数从 `null` 换成一个固定的 `CoreWebView2EnvironmentOptions`，参数行为
    `--disk-cache-size=8388608 --gpu-disk-cache-size-kb=8192 --disable-component-update --disable-features=OptimizationHints,OptimizationGuideModelDownloading,Translate,MediaRouter,MSOfficeLinkHandler`
  - `CacheDir()` / `DirSize()` / `Mb()`：算 `Store.DataDir\webview` 的真实体积，用于界面显示。
  - `WipeCacheIfFlagged()`：启动最早期（消息循环起来之前）检查 `cache-clear.flag`，命中则整目录删掉 `webview`，再启动 WebView2 —— 因为目录正在被占用时删不掉，只能等下次启动。
  - `PushCacheInfo()` / `ClearCache()`：处理设置页发来的 `getCacheInfo` / `clearCache`，前者回 `cacheMb`，后者落标记文件并回 `cacheCleared`。
  - `OnSettingsMessage` 增加这两个分支。
- `src/settings.html`（+4 行）：`#promptHint` 之后加 `#cacheClear` 按钮 + `#cacheHint` 说明行。
- `src/settings.js`（+12/-4 行）：`#cacheClear` 点击 → `say({type:"clearCache"})`；`state()` 处理 `cacheCleared` / `cacheMb`；`say({type:"ready"})` 后追加 `say({type:"getCacheInfo"})`。
- `src/i18n.json`（+36 行）：9 语言 × 4 键（`cacheBtn` / `cacheHint` / `cacheDone` / `cacheFail`），插在各自语言的 `skillPromptFail` 之后。
- `shell/Lang.Generated.cs`（+36 行）：`build.mjs` 重新生成，**生成物，不许手改**。

## 原因

商店写「不到 1MB」，装完却是约 10MB；用户加载 3D 壁纸后亲眼见到约 70MB，怀疑是虚假宣传。

真机拆解后发现，这个 70MB 的归因**只对了一小部分**。旧 profile 72.5 MB 的真实构成（实测，304 文件）：

| 目录 | 体积 | 是什么 |
| --- | --- | --- |
| `WidevineCdm` | 21.9 MB | DRM 解密模块，壁纸壳完全用不到 |
| `component_crx_cache` | 21.4 MB | WebView2 自己下载的组件包 |
| `Subresource Filter` | 12.3 MB | 广告过滤清单 |
| `GrShaderCache` | 4.7 MB | GPU 着色器缓存（3D 真实产生） |
| `Default`（含 `GPUCache` 1.6 / `Cache` 0.8） | 4.6 MB | 页面缓存（3D 真实产生） |
| `Speech Recognition` | 2.6 MB | 语音识别数据 |
| `hyphen-data` | 1.7 MB | 断词词典 |
| `BrowserMetrics` | 1.3 MB | 使用统计 |

也就是说：**约 59 MB 与壁纸无关，是 WebView2 默认行为下载的组件；跟 3D 真正相关的只有约 6 MB。**
所以能治，而且成本很低——不该为此藏起 3D 这个最大差异化。

## 影响

- **体积**：全新 profile 跑 6 分钟（同一张 3D 壁纸 `aurora-valley-3d.html`）为 **11.7 MB / 213 文件**，对比旧 profile **72.5 MB**，降幅约 84%。其中 `WidevineCdm` / `Subresource Filter` / `component_crx_cache` / `Speech Recognition` **全部为 0 MB**，抑制生效。
- **仍会长的**：`GrShaderCache` 4.6 MB、`ShaderCache` 0.5 MB —— 属于 3D 真实需要的着色器缓存，受 `--gpu-disk-cache-size-kb=8192` 约束，不会无限膨胀。
- **清理按钮**：删的是整个 `webview` 目录（比 `ClearBrowsingDataAsync` 彻底），因为目录在运行时被占用，实际删除发生在**下次启动最早期**，所以文案写的是"已清理，重启应用后完全释放"。
- **风险**：`--disable-component-update` 会同时关掉 Widevine。若将来要做「本地视频壁纸用 DRM 保护内容」——不可能（本地文件不需要 DRM），无需回退。若发现某项功能异常，回退只需删 `EnvOptions()` 里那两个开关型参数。
- **未改**：版本号（仍 `1.0.0.0`）、`AppxManifest.xml`、`version.mjs`。

## 踩坑（给下一个 AI）

1. **从 `out\` 根目录启动 exe 必崩**：`ExitCode=-532462766`（0xE0434352），事件日志 `System.IO.FileNotFoundException 在 PixelFX.Entry.WebView2Ready()` —— `out\` 根没有 `WebView2Loader.dll`。**从 `out\msix\` 启动**（dll 齐全）。这不是代码问题，别去改代码。

3. 用户机器上还有**另一个** WebView2 宿主（browser 进程 30704），查命令行时别拿错进程。
