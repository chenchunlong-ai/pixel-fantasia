# 2026-11-19 · 新场景「峡谷晨雾」gorgefall —— AI 底图 + 像素化 + 掩膜驱动瀑布

## 为什么要换方法

纯程序化"合成"峡谷（`src/fx/canyonfall.js` v1–v4：噪声团块崖壁 + 羽化瀑布）四版都不成立：
崖壁方块化、瀑布像浮空水柱/硬边管状、整体读不出峡谷。用户叫停，并指出国外能用代码做成电影，
一张壁纸却做不出——问题不在代码能力，而在**方法**：我一直在用噪声去逼近一张手绘构图，
还跳过了 96×60 剪影确认构图这一步。

改走的路线（用户点头的 C 路线）：
1. AI 出一张**绘画感底图**（构图由它负责，那是它擅长的事）；
2. 本地做**像素化**（限色 + 抖动）；
3. 代码只负责**让它动**：水、雾、光。构图、光影、材质全部锁在底图里，代码不再造形。

## 量化（在 harness 页面里跑）

注入 `__kmeans`（加权 RGB 距离 1.1/1.4/0.7、8 轮、固定种子 12345）、`__nearest`、`__quant2`：
3×3 中值去噪 → 饱和度 ×1.16 → 对比度 ×1.12 → k-means 取 k → 8×8 Bayer 抖动。
**采用 384×240 / k=16 / 抖动 22**（观感最像像素画）；k=28 更像"低分辨率照片"，320×200 更块状但构图细节丢。
产物在 `D:\AAAAA\ShiPin\1\work\fx-preview\q2-384-16.png`。

## 打包进源码

16 色按**亮度升序**排成 ramp（`PAL`），每像素 4 bit、半字节打包、base64 → 46,080 bytes / 61,440 chars，
`gorgefall.js` 约 67 KB。带抖动的图做 RLE 反而膨胀到 149 KB，所以放弃 RLE。
`plate()` 用 `atob`（无则 `Buffer`）解码，同时解出两份数组：`color`（`R|G<<8|B<<16|A<<24`）和
`idx`（每像素调色板索引）。`idx` 是这轮的关键——后面取掩膜要用它查亮度。

## 瀑布怎么动：从"人工量矩形"改为"从底图取掩膜"

前两版用 `FALLS` 三矩形 + 错相位条纹：坐标靠肉眼从网格图上读，**两次都读错**，
条纹画到崖面石头上（`zoom-fall-a.png` / `zoom-fall-v2.png` 可证）；退一步的"亮水像素列扫描"阈值过严
（`l>190` 只剩零星段）。教训：**不要在量化图上量坐标**。

改成自动掩膜 `wet()`：
- 调色板亮度 `0.299R+0.587G+0.114B`，阈值 **≥202**（只让 #d7d9c8=214 / #f8f9f2=248 两档进来，雾的 #bcc0b0=189 被挡在外面）；
- 限定 `x≥236`、`2≤y<202`（右侧崖壁区）；
- **再加一条列过滤**：该列亮像素数 `< 26` 就整列丢掉。没有这条，瀑布左边那片亮雾会被当成水，条纹飘在雾里像雪花噪点；
- 结果存成按像素下标的一维列表 `WET`（懒计算 + 缓存）。

## 条纹的形态（三次迭代）

| 版本 | 做法 | 观感 |
| --- | --- | --- |
| v3 | `y*0.6 + t*speed + (x%5)*4.2 + sin(...)` 相位，白/浅色三档 | 等长虚线，像雨丝 |
| v4 | 加逐像素 hash 抖动、长短不一 | 断成碎点，像静电 |
| **v5 采用** | 逐列偏移 `jc`（11）+ 逐像素偏移 `jp`（6），周期 30：`ph<2` 画 `#fbfdf4`（α0.6）亮边，`ph<10` 画 `#b3bfb4`（α0.3）暗带 | 亮的近白瀑布上**暗带**才看得见，列间相位差让带子斜着走，边缘参差 = 水流 |

关键认识：水本身已经是近白（#f8f9f2），再叠白几乎看不见；**动的是暗带**。

## 没做的

- 真机（exe）切换与宠物跟随未验收；exe 未重建（exe 只在发版前重建）。
- 60 KB base64 底图对"安装包不到 1MB"口径的影响：安装包 850 KB + 67 KB 源码仍在 1 MB 内，但用户尚未表态；
  若嫌大，可降到 320×200（约 43 KB）或 192×120 由代码放大。
- 这条路线可以复用：凡是"绘画感的场景"（地狱 3D、天堂、峡谷）都可以走"AI 底图 → 量化 → 掩膜/光照驱动"，
  代码只动亮度层，不造形。
